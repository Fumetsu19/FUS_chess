# Архитектура и план реализации

Приложение: **FUS chess** (`chess_english`), Flutter, только Android, только локальные данные, строго вертикальная ориентация. FUS = FU(metsu) + Strategy; слоган — Find Unique Strategy.

## 1. Анализ пакетов

### Шахматная доска: `advanced_chess_board 3.1.0` — выбрана

- Квадратная доска с `AspectRatio(1)`, корректно вписывается в ширину телефона; ориентация задаётся `boardOrientation`, вертикальный режим поддерживается.
- `ChessBoardController` построен на `chess 0.8.1`: легальные ходы, рокировка, взятие на проходе, превращение пешки (встроенный диалог выбора фигуры), мат, пат, ничья, PGN/FEN.
- Есть `enableMoves` — доску можно заблокировать до решения английской задачи и на время хода Stockfish.
- Есть `makeMove(from, to, promotion)` — движок может делать ход программно, включая превращение.
- Нет собственной сети/аккаунтов/таймеров, то есть не тянет лишние функции.
- Лицензия BSD-2-Clause, зависимости только `chess` и Flutter.

### Альтернатива: `chess_interface 1.2.1` — не выбрана

- Умеет рокировку, en passant и превращение, но завязана на собственный `ChessBoardProvider`, `FlutterArbiter` и таймер партии; интеграция с внешним UCI-движком и собственной блокировкой ходов менее прозрачна.
- В README пакета расходятся импорты (`chess_board_widget` и `chess_interface`), что повышает риск проблем при чистой сборке.
- Оставлена как задокументированная альтернатива, если `advanced_chess_board` когда-либо сломает совместимость.

### Движок: `multistockfish 0.6.1` — выбран

- Официальный пакет lichess.org, Stockfish 19, Android, встроенная лёгкая NNUE.
- API: `Stockfish.create()`, команды через `stdin` (`setoption`, `position`, `go`), вывод через `stdout`, `bestmove` парсится вручную.
- Один экземпляр на flavor; движок создаётся на партию и освобождается при выходе с игрового экрана.
- Лицензия GPL-3.0. Это важно для публикации: при распространении сборки с Stockfish нужно соблюсти GPL (открыть соответствующий исходный код/предоставить его получателям). Отмечено в README.

## 3. Данные и контракты

### JSON

- `assets/data/lessons.json`: корень `version`, `planned_total: 160`, `lessons[]`.
- Поля урока: `id, order, level, title, summary, theory.blocks[], vocabulary_ids[], exercises[]` — без изменений.
- Блок теории: `type ∈ {text, example, note}`, `content`.
- Упражнения: `multiple_choice` (`options`, `correct`), `fill_blank` (`answer`, `accepted`), `build_sentence` (`words`, `answer`), плюс `id/prompt/hint`.
- `assets/data/vocabulary.json`: `version`, `words[]` с полями `id, en, ru, transcription, part_of_speech, example_en, example_ru, lesson_id, level`.
- `assets/data/b1_reading.json`: пять B1-текстов с вопросом и тремя вариантами для итогового теста (дополнительный ассет, основные контракты не меняет).

Сейчас: **160 уроков** (40 A1 + 40 A2 + 80 B1), **642 слова**, **800 упражнений**. Количество уроков не зашито в код: все экраны читают JSON, прогресс — из SQLite. В уроке 1 — 20 слов, в уроке 2 — 16; TaskPicker не повторяет слово в одной партии, пока пул не исчерпан.

### SQLite

DDL из `SQLite.sql` переносится **дословно**: имена таблиц/полей не меняются. Дополнительные колонки в эти таблицы не добавляются.

- `srs_cards` — карточка слова, интервал, ease, число успешных повторений, дата следующего показа, последний результат.
- `lesson_progress` — завершение урока и статистика упражнений.
- `session_stats` — одна запись на учебную/свободную сессию; создаётся при старте, инкрементально обновляется после каждой задачи/хода, закрывается итогом партии. Это позволяет не потерять дневную статистику при выходе.

### Где хранится адаптивность

В DDL нет полей для «3 ошибки за 7 дней» и серии MC-ответов. Чтобы не менять контракт БД, эти вспомогательные счётчики хранятся в `shared_preferences` (`WordAttemptLog`, `AdaptiveStore`). Основной прогресс (SRS, уроки, сессии) остаётся в SQLite. Сброс прогресса очищает и БД, и вспомогательные ключи; настройки темы/звука/уровня при этом сохраняются.

## 4. SRS (упрощённый SM-2)

- Первый показ: карточка `interval_days=1, ease=2.5, reviews=0, next_review_at=now+1d`.
- Correct: `reviews++`, `interval=round(interval*ease)`, `ease=min(2.5, ease+0.1)`, `next=now+interval`.
- Wrong: `interval=1`, `ease=max(1.3, ease-0.2)`, `next=now+1d`; `reviews` не увеличивается (буквально по контракту).
- «Перестрелка»: меняет только `ease` и `reviews`, не трогает `interval/next_review_at`.
- Приоритет задач перед ходом:
  1. просроченные карточки (`next_review_at <= now`), сначала слова с ошибками за 7 дней, затем `last_result=wrong`, затем меньший ease/более старый срок;
  2. слова текущего урока, которых ещё нет в SRS;
  3. слова из завершённых уроков;
  4. fallback — слова текущего урока (чтобы первый урок не остался без задач).
- «К повторению сегодня» = `COUNT(*) WHERE next_review_at <= now`.

## 5. Игровой цикл

1. Статья урока (блоки text/example/note).
2. 3–5 упражнений; ответы проверяются нормализацией (регистр, пробелы, пунктуация); 3 попытки, затем показ ответа.
3. Урок фиксируется в `lesson_progress`; открывается партия.
4. Перед каждым ходом белых — word task из `TaskPicker`: 3 попытки, «?» — подсказка, после третьей ошибки — правильный ответ. До завершения задачи `enableMoves=false`.
5. Ход игрока → классификация звука → ход Stockfish (Skill Level + depth + movetime по уровню) → следующая задача.
6. Подсказка по ходу: в обучении автоматически, в лёгком режиме по кнопке, в основном режиме после решения задачи. Подсказка не задаёт дополнительный вопрос.
7. Мат/пат/ничья/выход → `ResultsScreen`: итог, задачи, first-try, слова на повтор, кнопки.
8. Если соперник рокируется, под доской появляется спокойное пояснение.

Уровни (в UI технические Skill-подписи скрыты):

| Уровень | Skill Level | depth | movetime | Особенность |
|---|---|---|---|---|
| Лёгкий | 0 | 1 | 40 ms | 45% случайных легальных ходов, подсказки |
| Средний | 0 | 1 | 80 ms | бывший лёгкий |
| Высокий | 8 | 10 | 900 ms | бывший средний |
| Эксперт | 18 | 18 | 2500 ms | полная сила |

Сила движка и уровень английского независимы. При недоступности нативного движка партия не блокируется: включается резервный случайный легальный ход и показывается предупреждение (Stockfish остаётся основным путём).

## 6. Этапы

1. **Data layer**: модели → JSON-парсер с валидацией → SQLite DDL → репозитории.
2. **Контент**: 160 уроков, 642 слова, 800 упражнений, проверка ссылочной целостности.
3. **Main UI**: тема, главное меню, уроки по вкладкам A1/A2/B1, словарь, настройки, профиль.
4. **Engine**: обёртка `multistockfish`, UCI, уровни, fallback, тесты парсера.
5. **Связка уроков и игры**: сессия, задачи перед ходом, блокировка доски, защита от повторов, результаты.
6. **SRS + адаптивность**: SM-2, приоритеты, перестрелка, счётчики, MC → fill_blank.
7. **B1-тест**: сборка 30 вопросов, 5 reading-текстов, порог 70%, отчёт по разделам.
8. **Обучение шахматам**: гид по шести фигурам и особым правилам, тренировочная партия с автоматической подсказкой каждого хода и пояснением рокировки соперника.
9. **Звук/темы/полировка**: WAV, light/dark, вертикальная ориентация, брендинг FUS.
10. **Проверка**: `flutter analyze`, 33 unit/widget теста, `flutter build apk --debug` и `--release`; release установлен на Android-эмулятор, Stockfish отвечает на ходы (Android — единственная целевая платформа).

## 7. Ограничения и решения

- **Нет бэкенда и сети** — контент из assets, всё остальное локально.
- **Вертикаль** — `SystemChrome` + `screenOrientation="portrait"` в AndroidManifest.
- **Контракты** — JSON и DDL не расширяются; для адаптивности используются prefs.
- **Прогресс не теряется** при смене темы/звука/уровня: эти настройки не трогают БД.
- **Уровни**: 40 A1 + 40 A2 + 80 B1; `planned_total=160`. B1-тест открывается после всех 80 уроков B1, проверяет грамматику/лексику/письмо/чтение и не является официальным сертификатом.
- **Лексика первых уроков**: урок 1 — 20 слов, урок 2 — 16, чтобы в первой партии не повторялись 3–4 слова; на игру ведётся список уже показанных слов.
- **Release/R8**: для `shared_preferences_android 2.5.1` в `android/app/proguard-rules.pro` добавлены шесть keep-правил из upstream-фикса [flutter/packages#13311](https://github.com/flutter/packages/pull/13311), иначе release падает с `NoSuchMethodError` на старте. После выхода исправленного пакета правила можно удалить.
